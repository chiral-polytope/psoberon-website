02 · Edit a record

No HTML editing.

Open the local editor, choose an existing paper or New record, and edit its metadata. The topics and student-coauthor fields control the corresponding lists automatically.

Download the JSON record and place it in content/papers/. The editor is a local helper, not a hosted account or automatic file uploader.

Talks/videos and separate research notes have their own collections in the same editor.

03 · Rebuild after editing

Run the local development server.

Install Node.js (Node 24 LTS recommended; Node 22+ supported). Open Terminal in this extracted folder. On a Mac, type cd , drag the folder into Terminal, and press Return.

npm run dev

Then open http://localhost:4321. The local editor is at http://localhost:4321/__editor/editor.html. Leave Terminal open; stop with Control+C. No package installation step is needed.

When you save source files, the server rebuilds and reloads the preview. Without a server, run npm run build after editing and reopen dist/index.html. Never edit dist/ directly.

04 · Before leaving Wix

Preserve the missing documents.

27 current Wix-hosted PDFs still need local copies. These include both CVs, teaching handouts, slides, and the current undergraduate geometry notes. Links use the old live site until the files are downloaded.

The archive's geometry notes have 77 pages, while the currently linked PDF has 111. The old copy is labeled as an archive; it is not substituted for the current notes.

Do not change DNS or cancel Wix until these files are saved and checked.

npm run recover:wix

Run this single command while the Wix website still works. It downloads the entire set into the correct folders and rebuilds the site. The Mac launcher RECOVER-WIX-DOCUMENTS.command does the same thing. All 27 URLs were readable through the browsing tool, but their original files could not be saved in this environment. The included report is not a completed backup. A manual download checklist provides every URL and exact save location. Read the report from the importer; network failures are not silently ignored.

05 · What to test

Review, then publish.

Review the site wording and imported bibliography in CONTENT-REVIEW.md. The proposed topic labels and descriptions are editable. Significance/context fields have been left empty for your own wording.

npm test
npm run check

This revision passed 32 automated source tests, local-link checks, and browser-render checks at six screen widths. External PDF downloads, video playback, your browsers, and actual deployment still need verification. Testing details and limitations.

For a temporary public preview, upload only dist/ to a static host. Leave preview_noindex on while testing. A noindex page is not private. Before final launch, download all required PDFs, complete the owner-review flag, turn preview_noindex off, and run npm run check:launch.
